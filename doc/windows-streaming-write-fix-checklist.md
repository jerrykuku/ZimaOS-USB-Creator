# Windows 流式写入与校验修复清单

发布标准：显示成功时，有清单哈希的源镜像必须已通过哈希校验；所有计划写入
设备的数据必须已经完成；程序最终修改的介质内容必须已经回读校验。

## 正确性修复

- [x] Windows 物理盘暂时固定使用缓冲同步 I/O，直到无缓冲对齐约束经过完整测试。
- [x] 原始镜像下载跨 curl 回调合并数据，只向 Windows 物理盘提交完整 4K 数据块，
  不通过逐回调补零来伪造对齐，避免开头即出现 error 87 或破坏镜像偏移。
- [x] FAT32 的 MBR、Boot Sector 和 FSInfo 恢复为精确 512 字节写入；不再为了
  “4K 对齐”扩写并清零相邻元数据扇区。
- [x] `Seek()` 在同步物理盘句柄上移动真实的 Windows 文件指针。
- [x] 将“成功但写入 0 字节”和校验阶段“成功但读取 0 字节”视为错误，避免死循环。
- [x] 区分“已经立即写入”和“延后写入”的首块，确保前者从 USB 实际回读。
- [x] 延后写入的首块在最终写入并刷新后单独回读，成功信号不会早于该校验。
- [x] 去掉校验前及周期刷新时重复的 Windows `FlushFileBuffers()`。
- [x] 检查校验 Seek 和缓冲区分配失败，不再从错误位置或空指针继续读取。
- [x] 校验过程中取消操作时返回取消，不记录为校验成功。
- [x] 从 URL path 判断原始镜像扩展名，带查询参数的 URL 不会误入解压链路。
- [x] 正确报告 buffered/direct-I/O 状态。
- [x] 修复异步提交立即失败时的 use-after-release 和 double-free。

## 需要执行的验证

- [x] 对修改文件执行 diff/空白一致性检查。
- [ ] 编译 Windows 目标；按要求由维护者执行。
- [ ] 在 512 字节逻辑扇区 USB 上完成写入和校验。
- [ ] 在 4K 扇区 USB 上完成写入和校验。
- [ ] 在回读前破坏首扇区，确认校验失败。
- [ ] 模拟零字节/短读取，确认校验失败而不是卡死。
- [ ] 分别在下载、写入、刷新和校验阶段取消，确认不会发出成功信号。

## 重新启用物理盘 IOCP 前的准入条件

- [ ] 根据设备要求对齐所有 buffer 地址、offset 和传输长度，包括最后的不完整块。
- [ ] 使用单一的专用完成处理者消费 IOCP，不再依靠生产线程主动轮询。
- [ ] 明确定义排队成功和立即失败时的 callback/buffer 所有权，并覆盖所有失败分支。
- [ ] 用严格的 cancel-and-drain 协议替换超时重放；内核仍可能引用时不得释放
  `OVERLAPPED`。
- [ ] 增加提交失败、短写、取消、完成包丢失和设备拔出等故障注入测试。
